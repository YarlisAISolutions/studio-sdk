# CLAUDE.md: studio-sdk

## What this repo is

The public, **read-only mirror** of the MyBotBox Studio SDKs:

- TypeScript: `@yarlisai/studio-sdk` on npm (`packages/ts-sdk`)
- Python: `yarlis-studio-sdk` on PyPI (`packages/python-sdk`). It imports as `mybotbox` (preferred) or `ystudio` (legacy).

Both are thin HTTP clients for the MyBotBox public API: workflow execution, run polling, agents, management, and device login.
Developers who call MyBotBox from their own code use them, and so do the `mybotbox` CLI and the MyBotBox team.
Docs: https://docs.mybotbox.com

**The source of truth is `YarlisAISolutions/mybotbox-platform`** (`packages/ts-sdk`, `packages/python-sdk`).
Its `scripts/mirror-studio-sdk.sh`, run by `.github/workflows/mirror-studio-sdk.yml` on every push to `main` that touches
those packages, regenerates this repo and pushes straight to `main` as `mybotbox-mirror[bot]`.
To change SDK code, open a PR on mybotbox-platform, not here. A code PR here cannot be merged: the next sync overwrites it.

## Layout

- `packages/ts-sdk/`: TypeScript SDK. `src/` holds the sources and the `*.test.ts` / `*.vitest.ts` tests. Also `examples/`, `CHANGELOG.md` (written by changesets upstream), `package.json`, `tsconfig.json` and `vitest.config.ts`.
- `packages/python-sdk/`: Python SDK. The implementation is in `ystudio/`, `mybotbox/` re-exports it, tests are in `tests/`, plus `examples/`, `pyproject.toml` and `setup.py`.
- `README.md`, `CONTRIBUTING.md`, `LICENSE`: generated by the mirror script on every sync.
- `CLAUDE.md`, `AGENTS.md`: this guide. The mirror script does not touch them.
- There is no `.github/`: CI, releases and publishing all run in mybotbox-platform.

## Setup

There is no lockfile here; the monorepo owns it. Node >= 20 and Python >= 3.10.

```sh
cd packages/ts-sdk
npm install --no-package-lock
```

Use `--no-package-lock` so you don't leave an untracked `package-lock.json` behind.
If npm reports root-owned files in `~/.npm`, add `--cache <some writable dir>`.

## Verify

TypeScript, run from `packages/ts-sdk`:

```sh
npx tsc --noEmit
npx vitest run --exclude src/copilot-models.sync.test.ts
npm run build:tsc
```

- Plain `npm test` (`vitest run`) **fails in this repo by design.** `src/copilot-models.sync.test.ts` is a drift gate
  that reads `packages/ai/src/copilot/models.ts`, and that file exists only in the monorepo. Exclude it here.
  Upstream, it passes.
- `npm run build` calls `bun run build:tsc`. Run `build:tsc` directly if you don't have bun.

Python, run from `packages/python-sdk` (this mirrors upstream `publish-python-sdk.yml`):

```sh
python3 -m venv .venv
.venv/bin/pip install pytest requests
PYTHONPATH=. .venv/bin/pytest tests/ -v
```

Clean up afterwards: `node_modules/`, `dist/` and `.venv/` are gitignored, but don't commit anything they leave behind.

## Conventions

- **Commits**: Conventional Commits (`chore:`, `feat:`, `fix:` …). The mirror bot always uses
  `chore: sync SDKs from monorepo @ <monorepo sha>`. The repo does not use a DCO or `Signed-off-by`.
- **Branches**: never push to `main`; only the mirror bot writes there. Agent work goes on `feat/<key>-…` or `fix/<key>-…`
  through a PR. YCadence items carry `Resolves <KEY>` in the commit footer and the PR body.
- **Releases and publishing** all happen upstream in mybotbox-platform:
  - TS: changesets bump the version and `CHANGELOG.md`, then `publish-packages.yml` publishes to npm.
  - Python: `publish-python-sdk.yml` runs the tests, publishes to PyPI if the `pyproject.toml` version is new, and creates a `python-sdk-v<version>` release.
  - Nothing is published from this repo.
- **Issues**: users file bugs here. Triage them, and fix them in mybotbox-platform.
- **Secrets**: never write API keys in examples or tests; read them from the environment (`MYBOTBOX_API_KEY`, `MBB_API_KEY`).
  Keys live in Yarlis Keep.

## Do not touch

- `packages/**`: the mirror script runs `rsync --delete` over both package directories on every sync, so any edit here is lost.
  Edit them in mybotbox-platform.
- `README.md`, `CONTRIBUTING.md`, `LICENSE`: the mirror script rewrites them from heredocs and the monorepo `LICENSE`.
  Change them in `scripts/mirror-studio-sdk.sh` upstream.
- `packages/ts-sdk/CHANGELOG.md` and the version fields in `package.json`, `pyproject.toml` and `setup.py`: changesets and
  the upstream release flow own them. A bump here would claim a version that was never published, and the next sync reverts it anyway.
- `src/copilot-models.ts` and `ystudio/copilot_models.py`: they are generated from `@yarlisai/ai` by upstream
  `scripts/sync-sdk-copilot-models.mjs`.
- Don't add CI workflows here. The repo has no verify pipeline, and a workflow would have to be kept alive in the mirror script.
